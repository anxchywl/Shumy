# Правила работы с Шумом

Прочитай `README.md` и документ, который отвечает за изменяемую часть проекта. Сохраняй существующую структуру и пользовательские изменения.

- `site/` содержит статический каталог. Сохраняй доступность содержимого без JavaScript и добавляй зависимости только при конкретной необходимости.
- `games/kto-iz-nas/` содержит самостоятельный игровой прототип. Изменения каталога не требуют изменения игрового сервера.
- `docs/PRODUCT.md` описывает сценарии, `docs/ARCHITECTURE.md` — технические границы, `docs/GAME_RESEARCH.md` — игровые идеи, `docs/DESIGN_RESEARCH.md` — визуальные решения и критерии просмотра.

## Каталог

- Сначала доступные игры, затем идеи. Добавляй действие только при наличии рабочего маршрута и называй его по реальному результату. Статус «Скоро» отображай текстом.
- Указывай требования до перехода. Не придумывай даты, вместимость, число игроков, отзывы или готовность функций.
- Описывай механику коротким естественным русским языком. Выразительность оставляй афишам и типографике. В интерфейсе используй простые формы, ограниченную палитру и заметный фокус. Избегай эмодзи и декоративных эффектов без задачи.
- Проверяй страницу визуально на широком экране и на телефоне, в том числе на ширине 320 CSS px. Сохраняй порядок чтения, клавиатурный доступ и читаемость статусов. Указывай границы проверки в отчёте.

## Изменения

- Пиши простой код с говорящими именами. Комментарии нужны только для неочевидной причины. Пиши их строчными буквами, без знака препинания в конце.
- Добавляй тесты по запросу или для конкретной регрессии, которую существующие проверки пропускают. Соблюдай ограничения текущей задачи на добавление и запуск тестов.
- Для публикации, деплоя, изменений сервера, DNS и Caddy нужно отдельное явное поручение. Не создавай коммиты и не отправляй изменения без запроса.
